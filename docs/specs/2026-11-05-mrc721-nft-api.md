# MRC-721 NFT Aggregate — Native manapi-Compatible API Spec

Status: implemented (branch `feat/mrc721-port`, commits f4c8999…R7).
Date: 2026-11-05.
Predecessor spec: [`2026-11-04-mrc721-sell-collection-api.md`](2026-11-04-mrc721-sell-collection-api.md)
(sell-intent index + upstream-refreshed collection views — unchanged there,
except the two collection views below gain a native source).

## 0. Architecture

MetaSo-P2P now indexes `/nft/mrc721` pins **natively** and serves the
man-p2p MRC-721 API surface byte-for-byte, so downstream consumers that
previously pointed at man-p2p switch their base URL to MetaSo-P2P and see
nothing else change. man-p2p stays a pure raw-pin indexer (and remains the
MANAPI pin/history source for bootstraps, as with every other metaso
feature).

- Package: `internal/aggregator/mrc721nft` (Pebble namespace `mrc721nft`).
  The sibling `internal/aggregator/mrc721` package keeps serving the
  sell-intent index (`/api/mrc721/sell/*`) unchanged.
- Live ingestion: confirmed chain pins only (aggregator `HandleBlockPin`),
  porting man-p2p's aggregation semantics exactly (see §2). Mempool pins do
  not fold into the aggregate; unconfirmed transfer visibility comes from
  the mempool pending channel (§4).
- History: hydrated from the manapi-compatible upstream read views by the
  offline bootstrap (§5) — the exact state downstream currently sees.

## 1. HTTP API (all GET, HTTP always 200)

Envelope mirrors man-p2p `api/respond` exactly:

- success `{"code":1,"message":"ok","data":...}`
- parameter/service errors `{"code":404,"message":"Parameter error."|"service exception.","data":null}`
- no-data `{"code":100,"message":"no data found.","data":[]}`

Pagination reads the legacy misspelled `cousor` first, then `cursor`
(int64 offset); `size` defaults to 20 and clamps at 200.

| Endpoint | Params | Notes |
|---|---|---|
| `/api/mrc721/collection/pageList` | cursor, size | name-keyed order, `{list,total}` |
| `/api/mrc721/collection/info` | `name` or `pinId` (name wins) | single collection DTO |
| `/api/mrc721/collection/items/pageList` | `pinid` (=collectionid) or `name`, cursor, size | ingest order; `total` = collection totalnum |
| `/api/mrc721/address/collection` | `address`, cursor, size | dedup collections, per-row `ownnum` |
| `/api/mrc721/address/item` | `address`, optional `pinId`/`name` filter | `total` counts all matches |
| `/api/mrc721/item/info` | `pinId` | item DTO + `pending` key only when an unconfirmed spend exists |
| `/api/mrc721/item/transfers` | `pinId`, cursor, size | `{list,total,pending}` — pending always an array, never merged into list/total |
| `/api/mrc721/item/verify` | `pinId` | indexed fact set + `itemGenesis`/`collectionGenesis` |
| `/api/mrc721/admin/replay-pins` | `pinIds` (≤100) | upstream state repair (§6), man-p2p response shape, no auth |
| `/api/tx/status` | `chainName`, `txid` | generic route; `found:false/txStatus:unknown` on RPC errors; `confirmed=false` ⇔ mempool |

DTOs emit the dual lowercase+camelCase spellings man-p2p emits
(`collectionname`/`collectionName`, `pinid`, `totalnum`, `txOutput`/`output`,
`txValue`/`outputValue`, `metaData`/`metadata`, `contentString`/
`contentSummary`, ...); `address`/`metaId` are the current holder.
**metaid 口径**: the `metaid`/`createMetaId`/`ownerMetaId`/`metaId` fields
carry the **global metaid** (IDAddress format, `pkg/idaddress`
`ConvertFromBitcoin` — the same convention man-p2p applies to its
`GlobalMetaId` fields). This deliberately diverges from man-p2p's MRC-721
DTOs, whose metaid fields still carry the legacy sha256(address) hex
("legacy metaid", sunset usage) — downstream consumers use global metaids,
derived locally from the address in both the live and bootstrap paths
(upstream metaid values are ignored). Unconvertible addresses yield "".
The collection search / issuer endpoints
(`/api/mrc721/collection/search`, `/api/mrc721/address/collections-issued`)
keep their IDBots wire shape (`{list,total,cursor}` with base64 cursor) —
they serve from the native read model once wired (§6), falling back to the
upstream-refreshed read model otherwise.

## 2. Pin semantics (ported from man-p2p `man/mrc721.go`)

Trigger: confirmed pins whose effective path (`<host>:` prefix stripped,
as man-p2p's `ValidHostPath` stores) lowercases to `/nft/mrc721/...`;
`collectionName` = path segment 4. MVC witness-format pins are excluded
(man-p2p's MVC adapter feeds OP_RETURN outputs only) — `PinInscription`
carries an `IsOpReturn` marker for this.

- `collection_desc` + `create` → register (first one wins); content keys
  case-insensitive, values verbatim; `totalSupply` default -1 (range
  [-1, 1e12]), `royaltyRate` default 0 (range [0,20]); invalid ⇒ pin ignored.
- `collection_desc` + `modify` → issuer-only version chain; idempotent by
  modify pin id; display fields overwritten wholesale; lowered totalSupply
  gates future mints only.
- `item_desc` + `create` → first-per-field backfill of item name/desc/
  cover/metadata; staged while referenced items are missing.
- any other segment + `create` → mint: supply gate, `Number = ++TotalNum`,
  `creatorMinted` = minter == issuer, genesis outpoint recorded
  (ledger-txid pointer + sat value).
- Out-of-order pins stage under `p:{collection}&{pinId}` and drain on
  registration (mints → descs → colmods in `(timestamp, pinId)` order).
- `metaId`/`ownerMetaId`/`createMetaId` values are **global metaids**
  (IDAddress conversion of the address, `pkg/idaddress`) — deliberately
  NOT man-p2p's legacy `sha256(address)` hex, which is sunset usage; see
  the metaid 口径 note in §1.

## 3. Confirmed transfers

Engine-side detection every block (including pinless blocks):

- `chain.TransferDetector` (optional per chain); the MVC implementation
  ports man-p2p's `GetOWnerAddress`: **ledger txid** pointers
  (`mvcMetaIDTxHash` — sha256d pointers are unresolvable on-chain for
  version≥10 txs), input-0 → output-0 fast path, cumulative input-value
  slow path, nulldata hex address, and the meltdown signature
  (≥3 tracked 546-sat inputs, one output, same addresses → burn).
- `aggregator.TransferConsumer` (implemented by mrc721nft): supplies the
  tracked outpoints (current item outputs, lazily cached) and applies
  notices through the hook — owner/holder-index re-key, provenance history
  `th:{item}&{height}{txid}` idempotent by `(itemPinId,height,txid)`,
  pending-channel settlement.

## 4. Mempool pending channel

Every 30s the engine fetches each chain's FULL mempool (with a
`chain.MempoolTransferDetector`) and routes one round to the consumers.
`mrc721nft` records advisory pendings `pt:{itemPinId}` (latest-wins per
item, `firstSeenAt` preserved on same-tx re-observation, reset on RBF
replacement; spend txid = ledger first segment of the location pointer) and
reconciles away chain pendings the round no longer observes. A failed
mempool fetch skips the chain — reconcile never runs on a partial
observation. Confirmation settles: the block hook's matching-spentOutpoint
deletion, and the pending surfaces via `item/info`'s conditional `pending`
key and `item/transfers`' always-present `pending` array.

## 5. Bootstrap (offline, daemon stopped)

```bash
go run ./cmd/metaso-p2p-mrc721-nft-backfill --data-dir <pebble data dir>
```

Three idempotent phases over the manapi-compatible upstream:

1. `collection/pageList` → collection records (DTOs are complete records,
   incl. genesis fields and the modify chain).
2. per-collection `collection/items/pageList` → item records + holder index.
3. per-item `item/transfers` → provenance history (dedup by the live hook's
   key; `transferCount==0` items skip the fetch).

Freshness rule: a stored item is only overwritten when the upstream row is
strictly ahead on `transferCount`; otherwise only empty desc fields fill in.
Re-runs fill gaps but never rewind live ownership. Flags: `--manapi-base-url`,
`--timeout` (8h), `--page-size` (≤200), `--skip-collections/--skip-items/
--skip-transfers`.

## 6. Deployment sequence

1. Deploy the binary (gate off — nothing changes).
2. Stop the daemon, run the bootstrap (§5), start the daemon.
3. Enable `METASO_P2P_MRC721_NFT_ENABLED=true` — the aggregate joins the
   registry: the manapi-compatible surface mounts, live ingestion + transfer
   detection + mempool channel start, and the collection search / issuer
   endpoints switch to the native read model (same wire shape).
4. Verify (§7), then downstream consumers switch base URL.

Config: `METASO_P2P_MRC721_NFT_ENABLED` (default false),
`METASO_P2P_MRC721_NFT_MANAPI_BASE_URL` (default `https://manapi.metaid.io`).
